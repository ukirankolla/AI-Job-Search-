# Noventra Mobile App

An Expo (React Native) app that wraps the Noventra web app in a native WebView.
This is how Noventra ships on the **Apple App Store** and **Google Play** while
reusing the existing Next.js web app.

## What it does

- Loads the deployed Noventra web app inside a native `WebView`.
- Opens anything outside the app's domain (links, mailto, tel, etc.) in the
  system browser instead of trapping users in the WebView.
- Provides in-app **Back / Forward / Reload** controls and an **Open in
  browser** action in a dark bottom toolbar.
- Keeps the web app's cookies, so sign-in (magic link / Google) works inside
  the app just like a browser.
- Uses the same slate-900 `#0f172a` "N" brand as the PWA.

## Stack

- Expo SDK 57, React Native 0.86, TypeScript
- `react-native-webview` for the web view
- `react-native-safe-area-context` for the toolbar
- `expo-splash-screen` for the native splash
- `expo-constants` to read the target URL from app config

## Prerequisites

- Node.js 20.9+ (same as the web app)
- An Expo account for cloud builds ([expo.dev](https://expo.dev))
- For store submission: an Apple Developer account ($99/year) and a Google
  Play Developer account ($25 one-time)

## Configuration

The URL the WebView loads comes from **`app.json` → `extra.webUrl`**
(currently `https://noventra.com`). Point it at your deployed Noventra site
before building a store binary.

## Scripts

From the `mobile/` directory:

| Command | Description |
| --- | --- |
| `npm start` | Start the Expo dev server |
| `npm run android` | Open on an Android device/emulator |
| `npm run ios` | Open in the iOS Simulator (macOS only) |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run doctor` | `npx expo-doctor` (project health) |

Icons and splash assets are generated by the root `npm run icons` script into
`mobile/assets/`; regenerate them whenever the brand changes.

## Building for the stores

Everything below assumes you have pushed a release to your Expo account.

1. **Point the app at your live site.** Deploy the Next.js app and set
   `extra.webUrl` in `app.json` to the public URL (e.g.
   `https://noventra.com`).
2. **Install EAS CLI** (from `mobile/`):
   ```sh
   npm install --save-dev eas-cli
   npx eas login
   ```
3. **Create the EAS project** (first time):
   ```sh
   npx eas init
   ```
4. **Build a preview / development build** to smoke-test the WebView, splash
   screen, and safe areas:
   ```sh
   npx eas build --profile preview --platform android
   npx eas build --profile preview --platform ios   # macOS only
   ```
   Test on a real device: WebView behavior, sign-in, the bottom toolbar, and
   that external links leave the app. A release build is the only accurate way
   to see the real splash screen.
5. **Create store builds:**
   ```sh
   npx eas build --profile production --platform android --no-wait
   npx eas build --profile production --platform ios --no-wait   # macOS only
   ```
6. **Submit to the stores:**
   ```sh
   npx eas submit --platform android
   npx eas submit --platform ios
   ```

The `eas.json` profile defaults are used unless you add your own. You may want
to enable **auto-submit** and add environment variables through the EAS
dashboard rather than committing secrets.

## App Store / Play Store checklist

- **Bundle IDs** — set once before the first build:
  - iOS `ios.bundleIdentifier` = `com.noventra.app`
  - Android `android.package` = `com.noventra.app`
  (Change them in `app.json`; they cannot be changed after the first store
  submission.)
- **Icons** — `mobile/assets/icon.png` is the 1024x1024 opaque store icon.
- **Splash** — configured by the `expo-splash-screen` plugin in `app.json`
  (slate-900 background, white N, `imageWidth: 200`).
- **Metadata** — name "Noventra", short description about AI-powered job
  search, screenshots, privacy policy URL, and the website URL.
- **Review guidance for a WebView app** — app stores occasionally scrutinize
  WebView-only apps. To reduce review risk: keep the in-app URL to your own
  domain, make sure external links open the system browser, and consider
  adding a couple of native touches later (e.g. native auth, push
  notifications) as the product grows.

## Known limitations

- The WebView requires a live, publicly reachable Noventra site.
- Offline usage is limited to whatever the web app's service worker caches;
  the native app does not add offline data.
- iOS builds require macOS + Xcode (or a cloud build via EAS).
